

## Create IAM Roles from CloudHub with Tags, Safe Deletion, and Audit Logging

This plan covers three enhancements: (1) a new edge function that creates IAM roles directly in AWS with tags, (2) a safe deletion flow that strips policies before deleting, and (3) an audit log table to track all role lifecycle events.

---

### 1. New Database Table: `role_audit_log`

A new table to record who created/deleted a role, what permissions were set, timestamps, and the AWS ARN.

| Column | Type | Notes |
|--------|------|-------|
| `id` | uuid | Primary key |
| `user_id` | uuid | Who performed the action |
| `action` | text | `created`, `deleted`, `permissions_updated` |
| `role_name` | text | e.g. `dev-ops` |
| `role_arn` | text | Full AWS ARN (nullable for failed creates) |
| `details` | jsonb | Permissions, tags, trust policy, error info |
| `created_at` | timestamptz | Timestamp of the event |

RLS: users can only view their own audit logs.

---

### 2. New Edge Function: `manage-cloudhub-roles`

A single edge function handling three actions:

**Action: `create`**
- Accepts: `roleName`, `description`, `maxSessionDuration`, `permissions` (optional service list)
- Calls `sts:GetCallerIdentity` to get admin ARN and account ID
- Calls `iam:CreateRole` with name `CloudHub-Project-<roleName>`, trust policy scoped to the admin ARN with `sts:ExternalId` condition, and **tags**:
  - `ManagedBy: CloudHub`
  - `CloudHubUserId: <userId>`
  - `CloudHubUserEmail: <email>`
  - `Environment: production`
- Calls `iam:UpdateAssumeRolePolicyCommand` to set max session duration (not needed -- `CreateRole` accepts it)
- Optionally attaches inline policies per selected service using the existing `SERVICE_ACTIONS` allowlist pattern
- Saves the role to `cloudhub_roles` table
- Writes an audit log entry to `role_audit_log`
- Returns the created ARN

**Action: `delete`**
- Accepts: `roleId`, `deleteFromAWS` (boolean)
- If `deleteFromAWS` is true:
  1. `iam:ListRolePolicies` -- get all inline policies
  2. `iam:DeleteRolePolicy` for each one
  3. `iam:ListAttachedRolePolicies` -- get all managed policies
  4. `iam:DetachRolePolicy` for each one
  5. `iam:DeleteRole`
- Deletes from `cloudhub_roles` table
- Writes an audit log entry

**Action: `listAuditLog`**
- Returns audit log entries for the current user

### 3. Updated Frontend Components

**`CreateRoleDialog.tsx`** -- Major rewrite:
- Remove the Role ARN input (auto-generated by the edge function)
- Add service permission checkboxes (EC2, VPC, RDS, CloudWatch, Security Groups) with read/write toggles
- Show a preview of the tags that will be applied
- On submit, call the `manage-cloudhub-roles` edge function with action `create`
- Display the resulting ARN in a success toast

**`RoleManagementTab.tsx`** -- Updates:
- Button label changes from "Register Role" to "Create Role"
- Delete dialog gets a checkbox: "Also delete the IAM role from AWS" (default off)
- Add an "Audit Log" expandable section at the bottom showing role lifecycle events (who, what, when)

**`useCloudHubRoles.tsx`** -- Updates:
- `createRole` calls the edge function instead of direct DB insert
- `deleteRole` accepts `deleteFromAWS` boolean and calls the edge function
- Add `fetchAuditLog` function

### Delete Flow Detail

```text
User clicks Delete --> Confirmation dialog with "Also delete from AWS" checkbox
  |
  +--> deleteFromAWS = false: Remove from cloudhub_roles only
  |
  +--> deleteFromAWS = true:
         ListRolePolicies --> DeleteRolePolicy (each)
         ListAttachedRolePolicies --> DetachRolePolicy (each)
         DeleteRole
         Remove from cloudhub_roles
         Log to role_audit_log
```

Failures at any AWS step are caught and reported but still remove the DB record (with error details in the audit log).
